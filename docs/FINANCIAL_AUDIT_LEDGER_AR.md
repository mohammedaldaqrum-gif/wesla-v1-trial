# دفتر اختبار المقارنة المالية — وِصلة جملة V1.0.1

الغرض: تسجيل قياسات ما قبل/ما بعد لكل سيناريو. لا يُعتبر الاختبار ناجحًا بمجرد تشغيل الواجهة؛ يجب مقارنة القيم الفعلية في قاعدة بيانات الاختبار.

## القواعد المرجعية
- كل القيم المالية تُخزّن بالمليم كأعداد صحيحة.
- المنتج يُقفل باستخدام SKU الموحد فقط؛ الاسم للعرض وليس مفتاحًا ماليًا.
- أجرة الشحنة محفوظة مرة واحدة لكل (batch_id, supplier_id).
- إعادة المخزون لا تتم إلا مرة واحدة لكل سطر.
- الغرامة مطالبة تسوية مستقلة؛ لا تخصم تلقائيًا من دين المحل.
- الإرجاع الجزئي يعالج سطر الصنف المحدد فقط.
- النسخ الاحتياطي يجب أن يتم عبر `VACUUM INTO`، لا بنسخ ملف SQLite نشط مباشرة.

## استعلامات قياس مقترحة

```sql
-- المخزون
SELECT id, stock FROM products WHERE id = ?;

-- الرصيد الائتماني المستخدم
SELECT COALESCE(SUM(reserved_credit),0)
FROM orders
WHERE shop_id = ? AND method='credit'
  AND status IN ('pending','ready','shipping');

-- الفاتورة
SELECT id, total, paid, status FROM invoices WHERE id = ?;

-- بنود الفاتورة
SELECT id, sku, line_total, unpaid, supplier_unpaid
FROM invoice_lines WHERE invoice_id = ? ORDER BY id;

-- عهد الخزينة
SELECT id, amount, status, current_holder_id
FROM cash_custody WHERE invoice_id = ?;

-- أجرة الشحنة (سجل واحد لكل مورد/طلبية)
SELECT fee_amount, status
FROM shipment_fees WHERE batch_id = ? AND supplier_id = ?;

-- سلامة النسخة الاحتياطية (نفذها على نسخة الاختبار)
PRAGMA integrity_check;
```

## أدلة لازمة قبل اعتماد نتيجة أي اختبار
1. لقطة شاشة للواجهة والحالة النهائية.
2. قيم قاعدة البيانات قبل وبعد.
3. رقم العملية ورقم الفاتورة/العهدة.
4. اسم المنفذ ووقت التجربة.
5. حالة الاختبار: ناجح / فاشل / غير منفذ.

أي خانة نتيجة فارغة تعني «لم يُوثّق الاختبار»، وليس نجاحًا مفترضًا.
